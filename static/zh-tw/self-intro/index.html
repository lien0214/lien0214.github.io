可靠性這件事給我的經驗是：很多看起來像錯誤的東西，其實是已知的良性情況。所以我先把雜訊和真正的錯誤分開。雜訊的部分，我降低告警等級，並重構錯誤處理流程，讓這些情況被明確處理。真正的錯誤中，有幾個來自第三方 API 的不確定行為，我追查這些情況並更新處理邏輯。最後 5 個關鍵 API 的錯誤率降低了 10 到 15%，剩下的告警也變得真正值得注意。

多智能體強化學習中的個別智能體旋轉

2026.07 – 2026.10 · 論文 AAMAS 2027 審稿中

IIS logo

核心想法

共用同一個網路的智能體容易行為趨同，但團隊需要不同的角色。

既有方法讓每個智能體縮放共享特徵；我讓每個智能體也能旋轉它們，參數只多 6.7%。

7 / 8

對照實驗證明提升不只是來自多出來的參數

也如實報告表現較差的情況：隨機隊伍組成

連奕維 · 後端與系統工程師

12

簡單講一下研究。今年暑假我在中研院資訊所做研究實習，成果寫成論文，目前在 AAMAS 2027 審稿中。問題是：多智能體強化學習通常讓所有智能體共用一個網路，這會讓它們行為趨同，即使團隊需要不同的角色。既有方法讓每個智能體縮放共享特徵；我加入了個別智能體的旋轉，讓它們也能用不同方向看待特徵，參數只多 6.7%。在 8 張 StarCraft 測試地圖上，多數地圖學得更快，其中 7 張最終達到或超過基準。我也做了對照實驗，證明提升不只是因為參數變多，並如實報告表現較差的情境。我提研究不是因為要轉向 ML，而是因為它和 GPU 專案是同一種習慣：嚴謹的實驗和誠實的結果。
